# Main-study technical incidents

## 31 August 2026 — embedded Nvidia 502 treated as non-retryable

Study V2.1 collection began on 31 August 2026. The first three responses of the first
conversation were saved successfully. Its fourth Nemotron request returned outer HTTP status
200 with an embedded Nvidia error code 502 and the message `Service temporarily overloaded`.
The worker preserved the error and all successful evidence, but classified the general
`provider_body_error` label as non-retryable.

The runtime recovery code was corrected to recognise only structured transient upstream codes
408, 429, 500, 502, 503 and 504. It retains the outer HTTP status separately and derives an
`upstream_http_<code>` recovery reason. Legacy `provider_body_error` messages are parsed with
safe literal parsing; malformed or unstructured messages remain non-retryable.

The correction does not change the model, prompt, context condition, repetition, seed,
generation-v4 settings or provider-routing policy. Existing raw events were not edited. The
original turn-4 event remains stored, and successful turns were not regenerated by this work.
Offline reconstruction reproduced its request hash exactly:

`857f65607f6ba8256c11f45342fe133e6e914f2f4628d29523e9d180b8d1ffe8`

Before this correction was applied, later manual resumptions had already completed the first
conversation and reached a second Nemotron conversation. The latest stored interruption had the
same embedded upstream 502 classification. Its next request was also reconstructed from disk and
matched the stored failed-request hash. No live request was made while implementing or testing
this technical runtime/recovery correction.
